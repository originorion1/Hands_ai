## Error handling and rollback boundary

On any in-process failure, stop before further mutation and roll back **only** resources created by this transaction, in reverse order. Before removing a new unit file, marker, resolver file, link, nft rule/table, or namespace, require its recorded inode/index/handle plus full expected content or semantic identity to still match. Remove new unit files and reload systemd only when those identities match and no instance is active. Remove v2 nft rules by recorded handles plus exact v2 comment/expressions; never sweep by a broad prefix. Remove the veth only if both recorded interface indexes, namespace inode, addresses, and zero process use still match. Remove the new namespace only if its observed inode still matches and it has no processes. If any identity changed or the process crashed before it recorded ownership, leave the resource isolated, report `ROLLBACK_INCOMPLETE`, and require human inspection. Do not invoke old cleanup scripts or touch any historical marker, directory, unit, session, receipt, or stash.

Successful staging still leaves `collision_clearance=false` pending review of the runtime receipt. Durable two-total-GET accounting across all service instances and restarts is a separate pre-customer-I/O gate; `MaxConnections=1` is only a concurrent-instance limit. DNS/TLS qualification and unsigned packet preparation remain separate future steps.
