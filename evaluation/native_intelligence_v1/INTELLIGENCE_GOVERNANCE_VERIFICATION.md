# Intelligence governance verification

The experimental selector is a pure proposal module. `eligible_questions` checks tenant agreement, a concrete understood resource, explicit `DiscoveryAuthorization`, calibration reference verification, and hard request/privacy/operational limits before calculating utility. `run_case` invokes `run_governed_discovery` for each bounded record read. `execution_allowed` is false in every prediction. No connector registration, credential API, permission-issuing API, model-generated instruction, execution port, or trusted-knowledge promotion was added.

Focused tests deny cross-tenant understanding, unauthorized targets, forged calibration, non-finite priors, over-budget or risky questions, poisoned answers, and altered source digests. The scorer rejects missing/duplicate method results, changed source refs/digests, changed tenant/source/run/report identities, non-read-only execution, and requests beyond the two-read contract. A later evaluator-integrity correction recomputes training calibration from pinned source records before accepting a benchmark run. These tests validate this synthetic harness and the new proposal module. Inherited portal/session, connector, evidence-custody and revocation tests are run with the full suite; this mission does not claim a new live connector or session revocation test through the selector.

Threats and limits: malicious source text is treated as data, with only `flag`, `clear`, or `missing` accepted; a digest of data is not a signature or independent custody witness. A caller-supplied calibration verifier can be dishonest; the evaluator closes that local gap by recomputing training calibration, but production would need a custody-backed verifier. Stale calibration under transfer shift caused four false positives. The experiment does not model runtime expiry or mid-read revocation itself, so production wiring must continue using the Kernel's authorization and revocation checks. Restart, credential, and browser isolation remain inherited contracts and need exact installed-runtime requalification before release. No claim of independent security approval is made.

Governance verdict: no authorization expansion observed in the new offline path; broader production security qualification remains pending independent review and stable-Linux execution.
