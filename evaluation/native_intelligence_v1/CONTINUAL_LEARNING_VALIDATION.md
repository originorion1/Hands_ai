# Continual-learning validation

The existing `PredictionLedger` records pre-outcome predictions with issue time, evidence cutoff, horizon, model version, cohort and evidence UUIDs. It checks prediction/outcome temporal order and exact replay. `ModelRevision` requires evidence from resolved prior outcomes; `organizational_cycle.py` compares a revised probability to a frozen 0.5 baseline on disjoint evaluation source/authorization domains. Existing `tests/test_prediction_ledger.py` and `tests/test_organizational_learning_cycle.py` cover replay, wrong evidence, cohort matching and version changes. The ledger explicitly delegates source authenticity to its caller. Revision records are versioned, but no automatic production policy promotion or permission expansion occurs.

This mission did **not** obtain independent adjudication, outcome provenance from a customer, a replay-validated strategy improvement, a forgetting test across old domains, or a qualified rollback of deployed strategy behavior. The new selector calibrates on designed training labels; that is offline supervised fitting, not validated continual learning. `frozen_nonlearning` equals `existing` in this lab, so the benchmark contains no proven learning gain. A reviewer must validate outcomes before any trusted strategy update. Rollback should select a prior immutable version after a failed held-out gate; no such production rollout occurred.

The next falsifiable experiment must time-seal predictions before outcomes, independently verify outcome records, freeze old-domain evaluation cases, update only a versioned strategy from admitted outcomes, compare paired held-out new-domain and old-domain loss to the frozen version, and reject updates that forget or expand authority. Until then **OUTCOME_LEARNING = NOT_PROVEN**.
