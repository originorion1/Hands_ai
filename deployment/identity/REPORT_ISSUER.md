# Independent report identity preparation

No ORION identity issuer, signing key, public key path, or persistent report
host is verified as provisioned. The paths below are a deployment contract,
not installed resources or working URLs. Do not put a signing key, passphrase,
token, tenant identifier, or subject in Git, Vercel, shell arguments, or logs.

The report host trusts one owner-only `orion.report-access.v1` JSON policy at
the path named by `ORION_REPORT_ACCESS_POLICY_PATH` (proposed host path:
`/etc/orion/report-access-policy.json`). The policy contains exactly
`policy_version`, `issuer`, `audience`, `tenant_id`, `allowed_subjects`, and
`ed25519_public_key`. The key is a 32-byte raw Ed25519 public key encoded as
unpadded base64url. The `issuer` must be the owner-controlled issuer URI,
`audience` the exact report-service audience, and subjects an explicit
allowlist for this one tenant. An independently administered issuer must hold
its own copy of the reviewed policy. No public JWKS URL is required by the
current verifier; the host policy is the authoritative verification-key and
trust-policy path. The host and issuer copies must be reconciled by their
owners before issuing tokens. Do not substitute Vercel SSO for this trust.

The source-only `deployment.identity.issue_report_token` tool prepares one
token from an encrypted PKCS#8 Ed25519 private key on a **separate identity
host**. The key and passphrase are supplied by that host's owner-managed
secret storage and are never generated by this repository. The tool reads
the subject and passphrase from separate file descriptors, checks that the
subject is allowlisted and the key matches the policy, then writes one
exclusive token file inside a 0700 owner-only directory. It prints no token.
The identity host operator controls how that file reaches its authorized
reader. This is an administrative issuance path, not a user login service;
customer login and production signing remain unqualified.

Tokens use EdDSA JWT with exact `iss`, `aud`, `sub`, `tenant_id`,
`scope=orion:report:read`, `iat`, `nbf`, and `exp` claims. The issuer tool fixes
the lifetime at five minutes; the report verifier rejects tokens over 15
minutes and accepts at most 30 seconds of clock skew for `iat` and `nbf`.
The report host rechecks signature, claims, allowlist, and tenant on every
data request. Wrong audience, tenant, subject, scope, signature, or expiry
fails closed. The signing key must never be installed on the report host or
Vercel, and the report host must not expose an issuance route.

To revoke a subject, stop issuance for that subject and atomically replace
the report host's owner-only policy with the subject removed. The next
request is denied without a restart. To rotate the signing key or revoke
all outstanding tokens, install a new owner-approved public key in the host
policy and change the independent issuer to the corresponding encrypted
private key. The report host accepts one key at a time; old tokens become
invalid immediately after policy replacement. A missing policy fails
readiness and report access closed. Individual token revocation is not
implemented; revoke its subject or rotate the key, and investigate the
exposure before restoring issuance. Keep a private audit of issuance and
policy changes on the issuer and host infrastructure; no audit service is
provisioned by this branch.

Before production activation, the owner must provision an identity host and
secret manager, TLS report host, private policy custody, controlled token
delivery, and an issuance audit. Record the actual issuer URI, host policy
path, key reference, revocation operator, HTTPS report URL, and health and
readiness results only after direct verification. Configure
`ORION_REPORT_BACKEND_URL` in the Vercel preview only after the HTTPS report
host and issuer have been qualified. Customer ERP access and production
grants require their separate authorization gates.
